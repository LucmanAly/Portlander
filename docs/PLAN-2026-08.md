## Revised plan

### P0 — Stop the data loss (half a day)

Two one-click paths currently destroy live data. Neither needs the larger refactor
to be made safe, and neither should wait on it.

**P0.1 — Guard CSV import.** `onCsv` calls `replaceHoldings(parsed)`, which
propagates a remote delete of every row not in the CSV — all 40 SnapTrade rows
included. Minimum viable fix: filter `source === 'snaptrade'` rows out of the
deletion set and preserve them in the replacement list. The full Merge/Replace
picker with a preview (plan 2.2) can follow.

**P0.2 — Clear the cache on sign-out.** Call the existing `clearAllData()` from
`signOut()`, and namespace the six `KEYS` in `storage.ts` by user id. Small, and it
closes a case where a signed-out browser still renders the real book.

### P1 — Data truthfulness (1–2 days) → plan Workstream 1

Do this before anything that consumes weights.

**P1.1 — Real macro dates.** Replace `buildMacroEvents()` in `sync-events` with a
static table in `supabase/functions/_shared/macro-calendar.ts`, then delete the 9
`macro-seed` rows and drop the generator in `src/data/macro.ts`.

*Deviation from the plan:* it asks for confirmed dates "through 2027". FOMC dates
are published roughly a year out and BLS release schedules about the same. Table
only what is officially published, mark those `status: 'confirmed'`, and emit
nothing beyond the published horizon — an empty calendar is honest, an extrapolated
one is the bug being fixed.

**P1.2 — Reconcile sold positions.** Build a `seenTickers` set per `snaptrade-sync`
run; delete `holdings` where `user_id = caller AND source = 'snaptrade' AND ticker
NOT IN seenTickers`. Skip the delete entirely if the run returned zero positions or
hit any per-account error. This is data integrity, not cleanup: a ghost position
inflates the denominator in `portfolioTotalValue()` and therefore silently skews
every other holding's weight and score.

**P1.3 — Three freshness clocks.** Read the newest `sync_runs` row *per provider*
(`finnhub`, `finnhub-quotes`, `snaptrade-positions`) and surface three labelled
timestamps.

### P2 — Tests, then mutation safety (2–3 days) → plan Workstreams 5 + 2, swapped

**This is the one ordering change.** The plan schedules tests last, but P3 below is
a rewrite of the exact code path that can wipe the book. Land vitest and the write-path
tests *before* the rewrite, not after it.

- Add vitest + a GitHub Action running `build → lint → test`.
- Cover first: source preservation across manual/CSV/SnapTrade, the P1.2
  reconciliation guard, and quote-refresh field patching.
- Then do plan 2.1 — replace `persistHoldingsRemote`'s select-all → delete-missing →
  upsert-all with per-row writes under the plan's authority model. The client stops
  sending `last_price` / `day_change_*` / `created_at` entirely.
- Then the full 2.2 Merge/Replace picker with preview counts, and a per-row delete
  confirmation.

Remaining coverage (exposure windows, date boundaries, event dedup, the earnings-
rescheduling characterization test) can land alongside P3.

### P3 — Make the score communicate (1–2 days) → plan Workstream 3

Depends on P1 for clean weights.

- **3.1** Mark rows falling back to `costBasis` as estimated rather than mixing cost
  and market value into one total; route `weightOverridePct` through
  `portfolioTotalValue()` so mixed books sum to 100%.
- **3.2** Replace `min(1, weight / 20)` with a portfolio-relative anchor. On today's
  book `max(5, p90 * 1.5)` ≈ 6.7%, turning a 39/49/78 spread into roughly 50/77/99.

  *Trade-off the plan doesn't name:* a portfolio-relative anchor makes scores
  non-comparable over time — a holding's score moves when *other* holdings move. That
  is acceptable because the score's job is ordering, but it is a real argument for
  **3.3** (High/Medium/Low labels): the words stay honest across rebalances in a way
  a bare number does not. Adopt 3.2 and 3.3 together, not separately.
- **3.4** Invert the card hierarchy — weight becomes the hero, score demotes to a tier
  badge, and delete the `EventCard` progress bar that duplicates the number above it.

### P4 — The morning read (optional, slice it) → plan Workstream 4

Genuine improvements, no correctness risk, safe to defer or take piecemeal. Highest
value first:

1. **4.1** Pass scored events to `MonthCalendar` and drive dot size from weight — the
   screen `AGENTS.md` calls the "position-weighted calendar" currently encodes no weight.
2. **4.6** Portfolio search / sort / source filter. At 41 holdings this is a real gap.
3. **4.5** Mobile: compact holding cards instead of the 640px-min scrolling table.
4. **4.2 / 4.3** Today lede and time grouping.
5. **4.7 / 4.8** Smaller fixes and the Settings IA rewrite.

### P5 — Deletions (an afternoon, any time)

Agreed with the plan, all verified dead or permanently empty:

- Dividends filter chip — no ex-div data is fetched in any sync path.
- Local sync path: `scripts/sync-events.mjs`, `src/lib/eventSync.ts`, the boot-time
  `applyLocalEventsSync()` calls (`PortfolioContext.tsx:123,245`), `public/data/`, the
  `sync:events` npm script, and the Settings section documenting it.
- `markSynced` / "Mark synced now" (`SettingsPage.tsx:133`) — writes a timestamp that
  reflects nothing.
- `getConfiguredFlag()`; the `src/hooks/` row in the `AGENTS.md` repo map (no such
  directory).

Keep the commercial SnapTrade branch. It works, it costs nothing at runtime, and
deleting deployed working code is churn — just document it as unsupported.

### Dropped, as the plan proposes

Multi-tenancy hardening (`sync_runs` missing `user_id`, `using (true)` RLS, global
`events` enumeration) is dead scope under personal-use-only. Also not now: AI
analysis, visual redesign, state framework, DB/hosting migration, tax lots, Phase 2
journals/alerts/prep cards.

## Execution order

```
P0  Stop data loss          (CSV guard, sign-out cache)          ← do first
P1  Data truthfulness       (macro dates, sold positions, clocks)
P2  Tests + CI, then mutation safety                             ← tests BEFORE the rewrite
P3  Score recalibration     (weight inputs, anchor, tiers, card)
P4  Morning read            (optional, sliceable)
P5  Deletions               (any time)
```

Rationale: stop losing data → stop serving wrong data → get a safety net → make the
score mean something → make it pleasant. The plan's own rationale, with the tests
moved ahead of the refactor they are meant to protect.
